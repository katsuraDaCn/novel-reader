# 「隐私书架」功能设计方案

## 一、功能行为（交互流程）

1. **隐藏**：在普通书架上**右键**某本书 → 弹出右键菜单 → 点「隐藏此书」→ 该书从书架消失，toast 提示"已隐藏，点右上角 🔒 查看"
2. **查看入口**：书架右上角新增一个低调的 🔒 图标按钮（无角标、不显眼）
3. **首次点击 🔒**：弹出"设置密码"弹窗（密码 + 确认密码 + 可选的密码提示语）
4. **之后点击 🔒**：弹出解锁弹窗（输入密码 + 显示密码提示）→ 验证通过进入「隐藏书架」视图
5. **隐藏书架视图**：顶部横幅「🔓 隐藏书架（N 本）」+「上锁」+「修改密码」按钮；书卡样式同普通书架；空态提示"右键普通书架的书籍可隐藏到这里"
6. **取消隐藏**：在隐藏书架中右键某本书 →「取消隐藏」（回到普通书架）/「删除」
7. **上锁**：点「上锁」回到普通书架并锁定；**应用重启自动回到锁定状态**
8. **错误保护**：连续输错 5 次密码，锁定 30 秒（倒计时显示，主进程侧实现，真实生效）

## 二、密码与安全方案

- 密码用 Node `crypto.scrypt` 加盐哈希后存 `data/security.json`（`{salt, hash, hint}`），**不存明文**；校验在主进程完成
- **忘记密码无法找回**（设计如此），只能删 `data/security.json` 重设
- **诚实的安全边界**：这是"防家人/同事随手翻电脑"级别的隐私保护。书籍文件本体在磁盘上仍是明文（`data/books/*.json`），懂技术的人直接翻文件夹就能看到。真正加密书内容成本高且影响打开速度，不建议在此版本做
- **关键设计——解锁前隐藏书对界面完全不可见**：`library:get` 默认只返回未隐藏的书，`book:get` 对未解锁的隐藏书直接拒绝。也就是说隐藏书的书名在解锁前不会进入渲染进程，就算有人按 F12 开开发者工具也看不到
- **隐藏操作本身不需要密码**（隐藏是无害、可逆的操作），查看/取消隐藏才需要密码

## 三、数据与接口变化

- `data/library.json` 每本书的 meta 增加 `hidden: true/false` 字段
- 新增 `data/security.json`（密码哈希）
- 新增 `lib/security.js`：纯 Node 的哈希/校验/冷却逻辑，可独立测试
- preload 新增 API：`security:status / setup / unlock / lock / change`、`books:hide`、`library:getHidden`
- main.js：`library:get` 加过滤、`book:get` 加守卫、新增上述 IPC 处理器

## 四、UI 实现

- **右键菜单**：用自绘 HTML 菜单（不用系统原生菜单）——理由：与应用主题风格统一，且浏览器演示模式下同样可用、可测试
- **密码弹窗**：自绘模态框，三种模式（设置/解锁/修改密码），支持 Enter 提交、Esc 关闭、输错时抖动提示
- **隐藏书架**：复用现有书架网格 + 顶部横幅条，是 `view-shelf` 内的一个子视图
- 浏览器演示模式（mock）同步实现这套接口（密码存内存/localStorage），保证 UI 仍可在浏览器中预览和自动化测试

## 五、测试与验证

1. `test/test-security.js`：哈希正确性、错误密码拒绝、冷却逻辑、hidden 过滤
2. Electron 自检启动无报错
3. 浏览器自动化走查全流程：设置密码 → 隐藏 → 上锁 → 重开 → 解锁 → 取消隐藏 → 修改密码
4. README 补充功能说明
